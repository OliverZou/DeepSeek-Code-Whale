这张架构图展示了一个名为 **“Leader · Worker · Verifier — 多 Task 对抗式协作”** 的工作流系统，其核心思想是通过角色分工、任务并行、阶段依赖和多轮对抗验证机制，实现高效、可靠的任务交付。整个流程由用户发起，经 Leader 编排，Worker 执行产出，Verifier 验证反馈，最终形成闭环交付。

以下是对图中每一个组件、箭头、角色和流程的详细中文描述：

---

## 一、整体标题与副标题

- **主标题**：  
  `Leader · Worker · Verifier — 多 Task 对抗式协作`  
  → 表明该系统基于三个核心角色（Leader、Worker、Verifier），支持多个任务（Task）并行处理，并采用“对抗式”协作模式（即 Worker 与 Verifier 相互博弈、迭代优化）。

- **副标题**：  
  `Leader 编排 · 多 Task 并行 · 多阶段链 · Worker ⇄ Verifier 多轮对抗`  
  → 概括四大关键特性：
  - Leader 负责任务规划与调度；
  - 多个任务可并行执行；
  - 流程分阶段（Stage），后阶段依赖前阶段产物；
  - Worker 与 Verifier 之间进行多轮“对抗”（类似研发 vs QA），直到通过验证。

---

## 二、主要角色与模块

### 1. User（用户）
- **位置**：左上角蓝色方框。
- **职责**：提出目标 + 接收最终交付成果。
- **交互**：
  - 向 Leader 提交目标（① 提目标）；
  - 从 Leader 接收最终交付物（⑥ 交付）。

> 用户不直接参与中间过程，只需输入需求、等待结果，体现“无需事无巨细介入”的设计理念。

---

### 2. Leader（领导者 / 编排者）
- **位置**：顶部中央橙色大矩形。
- **职责**：编排者 · 拆任务 · 派发 · 交付
  - 接收用户目标；
  - 制定计划（Plan）、拆分阶段（Stage）和具体任务（Task）；
  - 将任务分配给 Worker；
  - 收集各阶段 PASS 结果，汇总后交付给用户。
- **关键动作**：
  - ② Plan · 拆 Stage / Task → 向下输出到 Stage 1；
  - ⑤ Stage 2 PASS · 回 Leader 汇总 ← 来自 Stage 2 的反馈；
  - ⑥ 交付 → 返回给用户。

> Leader 是整个系统的“大脑”，负责全局协调与质量控制。

---

## 三、阶段划分与内部结构

系统分为两个主要阶段（Stage），用虚线框区分：

---

### ▶ Stage 1 · 并行 cycles（第一阶段：并行循环）

- **特点**：同 Stage 内多个 Task 各自独立 cycle，真并行。
- **包含内容**：
  - 任务 A → Worker A → 验证者 A
  - 任务 B → Worker B → 验证者 B

#### 子组件详解：

##### （1）任务 A / 任务 B（Task A / Task B）
- 形状：带折角的文档图标。
- 含义：具体的子任务单元，由 Leader 拆解而来。
- 流向：指向对应的 Worker。

##### （2）Worker A / Worker B（工作者）
- 形状：矩形框。
- 职责：“产出” —— 根据任务要求生成初步成果。
- 输出：
  - 实线箭头 → “停” → 触发 Verifier 开始验证；
  - 若被退回，则接收红虚线箭头“改”指令，重新修改产出。

##### （3）验证者 A / 验证者 B（Verifier）
- 形状：六边形。
- 职责：对 Worker 的产出进行审核、测试或校验。
- 行为：
  - 接收 Worker 产出后启动验证；
  - 若通过 → 推动进入下一阶段（③ Stage 1 全 PASS · 推进）；
  - 若不通过 → 发回“改”指令（红虚线箭头），触发 Worker 重做。

> 注意：Stage 1 中两个任务组（A 和 B）是**完全并行**的，互不影响，各自完成自己的“Worker→Verifier”对抗循环。
